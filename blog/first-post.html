BP01: Open Source Reflection

October 22, 2026

When starting out, open-source software is just things you use on the daily. You dont really think about the tools in the background, like Python or Flask. I didn't think about how the software is built or who actually maintained it. Once I started studying computer science, my perspective changed to the student view. Instead of just using the software, I began to actually read and work with it. I began to explore how things work. For example, we started off with the BCSR repository. I was able to see how a web app uses flask, jinja, and peewee. It wasnt just a site anymore, I was looking at a blueprint of a website. And then finally, I went from the studen view to an actualy contributor view. I was able to contribute to the BCSR repository by working on issues, pushing fixes, submitting pull requests, and even getting my own pull requests merged. This obviously came with roadblocks, coordination, communication, and consitency.

Pros and Cons

Open source software has its advantages and disadvantages. Becasue the codebase is open to anyone to see, the community is able to catch any bugs or make improvements to better the application. This type of collaboration and transparency, you will not see in a propietary software. However, at the same time, open source software can be a double-edged sword. Because the codebase is open to anyone, it can be difficult to maintain and manage. Projects can easliy be abandoned. Contributors come and go, can get burnt out, stop communicationg, or simply lost interest/busy. If consistency drops then, the project cna easily go outdated and fall apart.

Conclusion

So, is open source actually an effective model for building software? Even with its flaws, I think it is. As long as there is going to be consitency and communication. I think this because having a community means that code can get audited faster so bugs and security issues get caught alot faster than a propietary software. But for it to actually work, there is going to have meanigful code review, consitencty, and communication. I have seen this teamwork and maintenece play out while working on the BCSR repository. So far, I have completed 2 story points. My contributions have been focused primarily on imporiving the user experience and template rendering. The reason I only have 2 story points is because I overestimated the difficulty of a task, the issues I worked on turned out to be a lot simpler than I thought. This was also impacted by family emergencies and sickness. Balancing family, school, and work is a lot harder than I expected it to be. I really have to manage my time carefully as I don't have a lot of it. On top of that, all of us had issues setting up the local database environment. As a class, we spent the first few weeks just actually getting it setup on our laptops to be able to contribute, as well as understanding the application and how it works. This was a valuable experience because you are going to have to go through this everytime you contribute to an open source project.
